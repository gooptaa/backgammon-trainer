# GNU Backgammon Evaluator Adapter Spike

Timestamp: 2026-07-31-0714

Previous worklog: docs/worklog/2026-07-30-1948-evaluator-contract.md

Goal:

Add a focused Node-only GNU Backgammon evaluator adapter package that proves transcript-backed normalization into the existing evaluator contract, while keeping engine authority, analysis authority, browser exclusion, and truthful live-invocation boundaries intact.

GNU installation detection result:

- `command -v gnubg` returned no executable path in this environment.
- `gnubg --version` and `gnubg --help` were unavailable because the binary is not installed locally.

Observed GNU version:

- none locally observed
- capability fixtures and version parsing cover `1.08.003`

Live invocation verification status:

- live checker-play invocation remains unverified in this milestone
- no successful local GNU checker-play transcript was captured
- the package default request factory fails closed rather than pretending to know the command sequence

Package name and location:

- package directory: `packages/backgammon-evaluator-gnubg`
- package name: `@backgammon-trainer/backgammon-evaluator-gnubg`

Dependency direction:

- `@backgammon-trainer/backgammon-engine` -> `@backgammon-trainer/backgammon-analysis` -> `@backgammon-trainer/backgammon-evaluator-gnubg` -> future Node host
- no reverse dependency was added from engine, analysis, or web

Node-only boundary:

- Node process execution is isolated in `@backgammon-trainer/backgammon-evaluator-gnubg/node`
- browser bundles were not wired to this package
- no web GNU configuration UI or executable-path handling was added

Public adapter API:

- root exports:
  - `createGnuBgPositionEvaluator(...)`
  - `detectGnuBg(...)`
  - `parseGnuBgEvaluationOutput(...)`
- node subpath export:
  - `createNodeGnuBgProcessRunner(...)`
- testing subpath export:
  - fake runner helpers for transcript-driven tests

Capability result contract:

- distinguishes `available`, `unavailable`, `incompatible`, and `detection-failed`
- checks executable invocation, version response, help response, and advertised `--tty` / `--commands` support
- explicitly reports checker-play invocation as unverified even when capability detection succeeds

Process-runner contract:

- request fields:
  - `executable`
  - `args`
  - `stdin`
  - `timeoutMs`
- result states:
  - success with `exitCode`, `stdout`, `stderr`
  - failure with `unavailable`, `timeout`, or `spawn-failed`
- Node implementation uses direct `spawn(...)` with no shell interpolation

Process invocation strategy:

- manpage-grounded option support was limited to `--version`, `--tty`, `--commands`, `--no-rc`, and `--quiet`
- no live checker-play command file or stdin transcript was claimed as verified
- evaluator request building is therefore host-injectable and fail-closed by default

Timeout behavior:

- process runner kills the child process on timeout and maps to the shared `timeout` failure reason

Position translation representation:

- added a pure GNU-oriented board normalization model keyed to the player on roll
- representation stores 24 GNU-relative points with paired roller/opponent checker counts plus bar/off counts
- this model is used for deterministic translation, parser context, and future live-command serialization work

Point-orientation mapping:

- engine White direction remains `24 -> 1 -> off`
- engine Black direction remains `1 -> 24 -> off`
- White on roll maps engine point `p` -> GNU point `p`
- Black on roll maps engine point `p` -> GNU point `25 - p`
- White home board remains engine `1..6`
- Black home board remains engine `19..24`
- bar and borne-off counts remain explicit by roller/opponent ownership

Player-on-roll mapping:

- GNU-oriented normalization always treats the player on roll as the roller-facing side
- mirrored White/Black fixtures were added to fail if that orientation is reversed

GNU move parsing:

- added narrow coordinate parser for synthetic GNU-style step text:
  - `8/7`
  - `8/7*`
  - `bar/24`
  - `2/off`
- parser converts GNU-relative coordinates back to canonical engine coordinates using player-on-roll mapping

Canonical move matching:

- matching always uses the complete canonical legal move set supplied by analysis
- canonical move identity remains `getMoveFingerprint(canonicalMove)`
- notation never replaces canonical identity

Ambiguity behavior:

- unknown GNU move text is rejected
- coordinate-equivalent multi-candidate matches are rejected as ambiguous
- the adapter does not choose arbitrarily when GNU notation omits die-index identity

Score source:

- current parser only accepts explicitly marked `equity-points` transcript rows
- transcript format is spike-specific and synthetic for this milestone

Score perspective:

- transcript metadata declares either `player-on-roll` or `opponent-of-player-on-roll`
- opponent-perspective scores are sign-inverted during normalization

Normalized score direction:

- shared contract remains unchanged: higher normalized score is better for the player on roll

Score scale:

- adapter returns `equity` with `points` only when the transcript explicitly marks `equity-points`

Coverage policy:

- supports both `complete` and `partial` provider coverage
- partial coverage preserves warnings and relies on shared analysis to expose unevaluated legal moves
- no omitted move is fabricated

Provenance:

- successful results include:
  - `provider: "gnubg"`
  - observed or provided version, otherwise `unknown`
  - adapter version
  - JSON-safe settings
- current settings include only spike-safe facts such as executable basename, invocation-mode label, output-format label, and live-verification flag

Failure mapping:

- unavailable executable -> `unavailable`
- timeout -> `timeout`
- spawn or nonzero-exit failure -> `provider-failed`
- malformed transcript, unknown move, duplicate move, or ambiguity -> `invalid-provider-result`
- invalid checker accounting in translation -> `unsupported-position`
- raw stderr is not exposed in the user-facing error message

Deterministic settings:

- transcript fixtures explicitly carry deterministic/static labels where needed
- no rollout mode or heuristic fallback was added
- live determinism beyond transcript fixtures remains unverified until a real command transcript is captured

Transcript fixture origin:

- checker-play transcript fixtures are synthetic spike fixtures
- capability/version expectations are grounded in public `gnubg(6)` manpage text
- no synthetic transcript is described as captured real GNU output

Smoke command behavior:

- added `pnpm --filter @backgammon-trainer/backgammon-evaluator-gnubg smoke`
- command builds the package, detects GNU capability, and prints concise JSON-line status
- current local result: `{"status":"unavailable","message":"GNU Backgammon executable is unavailable."}`
- smoke command does not write repository files

Browser impact:

- none
- web app remains on no evaluator or explicit synthetic fixture evaluator only

Persistence impact:

- none
- GNU evaluation results remain transient and are not added to snapshots, history, or browser storage

Engine API impact:

- none

Shared analysis API impact:

- no behavior change to ranking, validation, or score-direction conventions
- only documentation was updated to describe the new adapter package boundary

Move-legality impact:

- none
