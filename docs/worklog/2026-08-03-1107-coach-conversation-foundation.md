# Text Coach Conversation Foundation

Timestamp: 2026-08-03-1107

Previous worklog: docs/worklog/2026-07-31-1105-architecture-guardrails.md

Goal:

Implement the first end-to-end text coaching conversation foundation with provider-neutral contracts, deterministic context/evidence assembly, fixture chat responses, and web chat UI integration without changing gameplay authority or persistence boundaries.

## Package placement decision

Decision:

- Keep `@backgammon-trainer/ai-contracts` generic and provider-neutral.
- Add `@backgammon-trainer/backgammon-coach` for backgammon-specific coaching conversation/domain orchestration.

Reason:

- Prevent generic AI transport contracts from importing deterministic backgammon domain contracts.
- Keep coaching context/evidence/prompt logic separate from engine, analysis, and analysis-session authority.

## Generic AI-contract impact

Refactored `packages/ai-contracts/src/index.ts` to generic chat-model transport contracts:

- `ChatModelRequest`
- `ChatModelResult`
- `ChatModel` interface
- provider-neutral failure taxonomy and provenance/usage types

Added deterministic fixture model subpath:

- `packages/ai-contracts/src/fixture.ts`
- package export `@backgammon-trainer/ai-contracts/fixture`

## Coach package APIs

Created package:

- `packages/backgammon-coach`

Implemented public APIs:

- conversation model + append helpers
- context resolver + precedence policy
- deterministic evidence builder with bounds/warnings
- knowledge retriever interface + no-op + fixture retriever
- prompt builder (`buildCoachModelRequest`)
- host orchestration helper (`submitCoachQuestion`)

## Conversation and message model

Implemented JSON-safe immutable conversation/message model with:

- explicit conversation/message IDs
- explicit timestamps
- trim + reject empty text
- duplicate message ID rejection
- stable append order
- no provider SDK objects

## Game-lineage lifecycle

Implemented policy:

- one conversation per active game lineage
- new game resets conversation
- successful imported lineage replacement resets conversation
- browser restore loads game snapshot but starts empty conversation

No conversation persistence added.

## Context types and precedence

Implemented:

- `current-position`
- `move-outcome` (explicit selected preview)
- `history-turn` (explicit selected turn)
- `game-review` (completed game fallback)

Precedence:

1. selected move outcome
2. selected history turn
3. current position
4. completed game review fallback

## Staged-selection policy

Staged selection is represented only as factual candidate intent summary:

- selected step path strings
- candidate move fingerprints
- candidate labels

Committed state remains authoritative.

## Evidence bundle

Implemented deterministic `buildCoachEvidence(...)` with:

- context kind summary
- position facts
- bounded legal move evidence rows
- canonical fingerprints
- feature deltas
- optional ranked fields (`evaluatorRank`, `normalizedScore`, `lossFromTopScoredMove`)
- evaluator provenance + coverage when available
- historical committed turn evidence
- game-review aggregate evidence
- conversation summary
- bounded warnings

## Factual/evaluator distinction

Evidence explicitly distinguishes:

- deterministic factual facts (position/outcomes)
- evaluator-attributed ranking metadata

No strategic claims are generated by the evidence builder.

## Fixture-analysis treatment

If evaluator provenance contains fixture provider identity, warnings are added and surfaced as synthetic fixture output.

## Historical and game-review support

Implemented support for:

- explicit selected historical turn evidence with missing-analysis warning
- completed-game aggregate evidence using supported metrics only

No fabricated historical scores.

## Knowledge-retriever boundary

Implemented provider-neutral retriever contract.

Included:

- no-op retriever
- deterministic fixture retriever

Failures are non-fatal for request construction and response flow.

## Prompt-builder behavior

Implemented deterministic prompt builder:

- preserves user question
- includes bounded recent conversation messages in order
- includes structured evidence and bounded knowledge
- includes explicit non-invention and provenance instructions
- avoids provider credentials and raw React objects

## Bounded-context limits

Implemented limits:

- max conversation messages: 8
- max chars per included message: 800
- max knowledge entries: 4
- max legal move evidence rows: 24
- max evidence warnings: 8

Truncation adds deterministic warnings.

## Chat-model contract and fixture model behavior

`ChatModel.complete(...)` is non-streaming and provider-neutral.

Fixture model behavior:

- async deterministic responses
- configurable delay and failure modes
- explicit fixture provenance
- controlled promise mode for stale-response tests
- fixture text states it is not strategic advice

## No-model behavior

Coach panel renders with no model configured and shows:

- `No coach model configured.`

Send is disabled; gameplay remains available.

## Server mock-endpoint decision

Decision:

- web core coaching flow uses injected fixture `ChatModel`
- existing server mock coaching endpoint is retained and updated to compile with new generic contract
- server endpoint is not required by core conversation-domain tests

## Accessibility

Implemented:

- labeled coach region
- labeled textarea
- send button label
- polite pending/failure status regions
- visible fixture warning text
- keyboard submission/newline behavior

## Mobile layout

App layout now stacks board and sidebar areas on narrow screens and preserves desktop split on wider screens.

Coach message history has bounded height; no horizontal overflow introduced.

## Request snapshot semantics and stale responses

Implemented:

- request captures context/evidence at submit time
- same-lineage late responses are accepted
- prior-lineage late responses are ignored
- one pending request per conversation

## Failure behavior

Handled non-fatal model failure states:

- unavailable
- authentication-failed
- rate-limited
- timeout
- provider-failed
- invalid-response

Failures do not crash app or gameplay.

## Persistence exclusion

No conversation/coaching persistence added to:

- game snapshot format
- local storage payload
- import/export payload
- analysis-session payload

## BYOM boundary and credential deferral

Prepared adapter boundary through provider-neutral `ChatModel` and prompt/evidence orchestration.

Intentionally deferred:

- provider SDK adapters
- API-key/OAuth flows
- credential storage strategy

## Voice architecture exclusion

No microphone, recording, speech synthesis, or real-time voice-agent architecture was added.

## Engine/analysis/session/evaluator/server impact

- engine API impact: none
- move legality impact: none
- analysis impact: none on factual/ranking contracts
- analysis-session impact: none on package contracts
- evaluator impact: none on evaluator contract behavior
- server impact: mock endpoint contract adaptation only, no real provider calls
