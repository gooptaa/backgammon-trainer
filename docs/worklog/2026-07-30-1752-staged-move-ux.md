# Move Review UX

Timestamp: 2026-07-30-1752

Previous worklog: docs/worklog/2026-07-30-1745-staged-moves-opening-roll.md

Goal:

Improve staged move construction interaction quality by adding step-back support, clearer candidate visibility, and richer breadcrumb feedback without changing engine move legality or introducing new game rules.

Undo interaction model:

- Replaced the previous selection control wording and behavior with `Undo Last Step`.
- Undo semantics are staged-only and non-mutating:
  - when staged steps exist, remove only the most recent selected step
  - preserve all earlier selected steps
  - clear pending selected source and hover destination state
- Repeated undo reaches an empty selection naturally.
- Committed state (`GameState.position`) is never changed by undo.

Candidate visualization:

- Added a `Remaining candidates` panel in the board workspace.
- Panel displays two human-readable groups:
  - `Continuations`: unique next-step options still legal from the current staged prefix
  - `Completed moves`: complete legal moves matching the current staged prefix
- Candidate rows are text-formatted move paths and include duplicate-match counts when applicable.
- No raw JSON is exposed.

Breadcrumb behavior:

- Breadcrumb still shows completed staged path in order.
- When a source is selected and destination is pending, breadcrumb now explicitly includes pending intent:
  - example: `13 -> 8 -> [select destination]`
- Pending-source-only state also renders as `X -> [select destination]`.

State-transition behavior on undo:

- Undo clears hover preview state.
- Undo recomputes staged projection from remaining selected prefix via existing `previewMovePrefix(...)`.
- Undo recomputes candidate move filtering and board highlights from the updated prefix.
- Undo never mutates committed game state or bypasses legality checks.

Engine API and rule impact:

- No engine files changed.
- No new engine APIs added.
- Existing `previewMovePrefix(...)` remained sufficient for staged step-back interaction.
- No move generation, legality, or application semantics changed.

  - breadcrumb shows pending destination with selected source
